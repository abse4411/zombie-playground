# 调研 · 丧尸多楼层寻路 + 攻击立体判定（v14.1~v14.3）

来源：Project Zomboid 楼梯寻路讨论、7 Days to Die Zombie AI Pathing 分析（LOS+路径选择+声音引诱）、
Roblox/Unity/GameMaker 开发社区（路标 vs NavMesh vs 转向行为）、Reddit r/gamedesign。

## 社区结论
- 楼层过渡（楼梯/梯子）是多楼层寻路的经典失败点；PZ/七日杀的丧尸通过"路径选择朝楼梯移动"解决
- 轻量路标导航 + 转向行为（分离/沿墙）是尸潮规模的标准解；完整 NavMesh/A* 对群疫模拟性价比低
- 无视线时需要"气味感知"式持续逼近（本作已有沿墙绕行 v4.2）
- 楼梯路标会被玩家利用做"断桥陷阱"（七日杀拆楼梯）——属特性而非缺陷

## 本作现状盘点
- 丧尸已支持爬台阶（groundHeightAt stepHeight 0.6 平滑爬升）+ 高处坠落摔伤
- 追击AI v4.2：双射线视线检测 + 无视线沿墙滑行 + 卡住换向 —— 缺"楼梯在哪"的感知
- **攻击判定 bug**：zombie.js dist 为纯 2D 水平距离（Math.sqrt(dx²+dz²)），
  楼下丧尸与楼上玩家 z 同位时 dist≈0 → 隔层攻击成立 —— v14.1 修复目标
- rooftops 图=两层购物中心+两部 staircase；snowOutpost 高台有踏步 props

## 方案（v14.2 楼梯导航）
1. staircase 构建器注册路标：底端(登梯点)+顶端(到达点) → ENGINE.navPoints（clearMap 清空）
2. 地图 JSON 可选 `nav:[{x,z}]` 数组，供手摆高台路标（如 snowOutpost 高台踏步处）
3. 丧尸转向：玩家高于自己 >1.4m 时，选「丧尸→路标 + 路标→玩家×1.5」代价最小的路标为临时目标，
   到达(<1.8m)或1.2s重估；高差消除后回归普通追击。丧尸高于玩家时直接走过去坠落（已有摔伤）
4. 攻击判定立体化（v14.1）： Melee/冲锋/风击/连击/自爆全部加 |dy|<1.6 门；
   爆炸伤害加垂直分量 |y-目标y|<半径；舔食者长舌同样门控；吐酸为抛物线不门控

## v14.3 狩猎保存/继续设计
- 存档点：波次间歇（wave clear）+ 手动"保存并退出"（暂停菜单）+ 退出自动保存
- 存内容：地图/难度/波次、玩家全量（位置/生命/护甲/金钱/perks/武器架+仓库+弹匣/投掷物/医疗包/体力）
- 恢复：继续=重开当前波次（刷怪重置，玩家进度保留）；主菜单"继续狩猎"入口显示进度；"放弃任务"清档
